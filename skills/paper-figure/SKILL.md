# Paper figures in PowerPoint

Produce PPTX, a preview rendered from that PPTX, and a short validation note; for draft-based creation, also provide the selected visual draft. Keep text, diagram shapes, cells and connectors native. Use independent picture objects for appropriate photographs, generated illustrations and pictorial icons; do not flatten the diagram to an image or one SVG. Use PowerPoint as the editor.

## Choose the work target

For a figure request, create or revise the requested artifact. For a skill-improvement request, including evaluation feedback supplied during skill development, update the reusable instructions and checks; do not substitute editing example figures for improving the skill. For a review-only request, report observations without changing the artifact. Use the ongoing task's scope to interpret pasted feedback.

For every new figure or substantial composition redesign, **generate and inspect a full-figure image-model draft before authoring the PPTX**, then rebuild its useful visual design with editable native objects and verify the saved result. This is a required production stage, not an optional technique. Generating only icons, sketching in code, inspecting a reference paper, or generating an image after the PPTX does not satisfy it. Read [image draft → native reconstruction](references/image-first.md) before starting. Preserve local edits to an existing PPTX; they do not require a new composition. Honor an explicit user instruction to skip drafting or to reproduce a supplied raster exactly, and record that route accurately. If image generation is unavailable, report the blocker instead of silently substituting direct PPTX authoring.

## Image provider

Use the available host image-generation tool by default. Do not surface external API choices, registration or credential checks during ordinary work or as a fallback after native-tool failure. Only when the user explicitly requests use or setup of the Gemini image API, read [the requested integration guide](references/gemini-image-api.md) and use the bundled `scripts/gemini_image.py` client with the configured Python runtime. A saved key, a generic image request or mentioning Gemini as a host does not select this provider. Reuse the explicit selection within the task. Keep the same image-first, editable reconstruction and saved-file review requirements.

## Create

1. Extract required labels, nodes, directed edges, hierarchy, repetition and training/inference distinctions into a content contract **before drawing**. Add a compact private relationship plan using [relationship planning and review](references/relationship-review.md): what each mark represents, whether an edge carries one item or a set, visible endpoints, identity across views, and any unspecified operation. Preserve supplied content; do not fill semantic gaps with invented mechanisms.
2. Choose the paper's intended width and aspect ratio. If unspecified, state a provisional width. Open and visually inspect relevant original figures from [reference cards](references/reference-cards.md) or the user's references. Identify the relationship each visual device explains and whether it applies to this method. Familiarity, complexity, photographs and thick arrows are not quality criteria by themselves.
3. Choose representations using [visual design](references/visual-design.md). Show meaningful inputs, state changes, spatial structure or a worked relationship where the method needs them. Trace the main path, a branch/merge and one recurring item before styling. Resolve gaps in endpoints, collection scope or axis correspondence before adjusting line weight. Choose a compatible [color book](references/color-books.md), or preserve the manuscript's established palette; record its semantic role mapping and use its fill/stroke/accent levels deliberately. Pastel is not an AI-authorship cue. Keep a simple overview when it adequately serves its purpose; do not add panels or decoration to make it harder to classify as generated.
4. Generate at least one **complete composition draft** with the image model from the content contract, selected references and color roles, following [image draft → native reconstruction](references/image-first.md). Inspect it before building. Save the actual prompt and draft, then record which layout, proportions, spacing and visual hierarchy to preserve and which semantic mistakes to correct. The draft may depict labels, formulas and arrows as visual guidance; none of those raster elements may serve as the final editable explanation.
5. Reconstruct the reviewed composition using [authoring](references/authoring.md) and `scripts/figure.mjs` with the bundled Artifact Tool runtime. Separately create the [inserted visual assets](references/visual-assets.md) when needed or requested; a full-figure draft does not fulfill an icon/illustration request. Small concept/function icons generally suit restrained pictograms; observations need meaningful sample imagery. Rebuild every required label, formula, state mark, diagram boundary and arrow natively. Follow [editable mathematical typography](references/math-typography.md) for formulas and indices, and the environment's Presentations implementation/finalization instructions. Examples demonstrate native construction techniques, not a substitute for the required draft stage or a composition to recycle. Independent content contracts are in `examples/tasks.json`.
6. Inspect the **exported** PPTX with `scripts/pptx.py inspect --contract` and `scripts/flow_audit.py`. A missing/reversed required edge is a semantic failure. The flow audit flags transparent anchors, unsupported geometry and coordinate gaps for rendered review; it does not decide visual quality. Render at full size and intended publication width and run the applicable checks in [relationship review](references/relationship-review.md). Compare the selected draft and saved-PPTX render side by side at equal width; check what visual quality survived reconstruction and record deliberate corrections. For mathematical labels, verify actual rendered fonts and script sizes using the [typography review](references/math-typography.md#review-the-saved-output); declared font names and native-object counts are insufficient. Verify symbol/state definitions against the intended caption and essential state distinctions in reduced grayscale; add timing correspondence only when the supplied method needs it. Follow [review and editing](references/review-and-editing.md) for preservation.
7. Classify findings as structural defects, conditional explanation improvements or finishing changes. Repair confirmed defects first and preserve successful regions. Do not force a fixed number of criticisms or add unspecified operators to satisfy a reviewer. Usually stop within three review rounds and state unresolved limitations. Before declaring completion, confirm the draft, actual prompt, transfer decisions and draft-to-render comparison are recorded. An icon-only generation or a native-object check is not evidence that this workflow ran. Link the selected draft alongside the final PPTX/preview and state any explicit route exception. Never claim an app edit test based on XML or a preview.

## Revise a user's PPTX

Use the latest saved PPTX. Inspect current objects and compare with the requested edit. Names and IDs can change after duplication, deletion or saving; combine the slide’s displayed position and inspected part, current ID, name, text, fingerprint and source hash. `scripts/pptx.py patch` supports conservative text replacement and simple translations, writing a new file. Read [review and editing](references/review-and-editing.md) for limits and preservation checks. Use native PowerPoint for operations outside those limits. Do not regenerate from old source code over human edits.

## Scope of assurance

Simple formula labels can use native text with validated script formatting; this is not a full Office equation editor. Use an actual equation object only when the authoring environment supports and validates it; do not claim that text runs are OMML. Groups and connectors require saved-file verification. Text and routed connectors can render differently across engines; use the bundled LibreOffice or PowerPoint to cross-check and identify the renderer actually tested. Do not re-export a human-edited file through Artifact Tool solely to render it.

Keep structural, visual, native-app and model-comparison results separate. See [evaluation](references/evaluation.md) for the eight tasks and four-condition protocol. Do not synthesize a comparison result by labeling handcrafted examples as independent model runs.

When a blind comparison or verifier is requested, use [blind review](references/blind-review.md). Keep the answer key out of the evaluator context, record recognition from memory, and separate source classification from visual quality. This diagnostic is conditional, not a mandatory extra model call for every figure.
