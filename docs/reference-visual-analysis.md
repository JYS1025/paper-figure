# 참고 논문 figure 재분석과 수정 방향

2026-09-29. MAE, CLIP, U-Net, Transformer의 아래 원본 figure를 브라우저에서 직접 확대해 관찰했다. 다음 평가는 원저자의 지침이 아니라 이 프로젝트의 시각적 해석이다. 논문의 성능 수치를 재평가한 문서가 아니다.

## 이전 결과의 문제

기존 예제는 편집성과 연결 구조를 확인하는 데에는 유용했지만, 논문 figure의 시각 품질을 보여주는 결과로는 부족했다. 서로 다른 의미의 입력·연산·출력을 비슷한 크기의 텍스트 상자로 만들었다. 정보가 없는 넓은 빈 공간, 반복되는 제목/파스텔 상자, 근거 없는 균등 배치가 모든 과제를 같은 도식처럼 보이게 했다. 중요한 표현을 독자가 라벨을 읽고 상상해야 했다.

구조 검증 15개 통과와 이미지 객체 0개는 이 문제를 해결하지 못한다. **사진을 배제하는 것이 편집성의 목표가 아니다.** 사진은 사진으로, 조작 가능한 설명은 네이티브 라벨·영역 표시·연결선으로 분리하는 것이 적절하다.

## 원본에서 확인한 차이

| 원본 | 실제 보이는 표현 | 설명에 기여하는 이유 | 이번 수정에 적용 | 그대로 복제하지 않을 것 |
|---|---|---|---|---|
| [MAE Fig. 1](https://arxiv.org/html/2111.06377v3/arch.png) | 가려진 사진 격자, 꺼낸 사진 조각, 짧은 visible-token 열, mask token이 섞인 긴 열, 크기가 다른 encoder/decoder | 픽셀 공간과 토큰 공간의 전환, 어느 지점에서 마스크가 들어오는지, 계산 비대칭을 라벨 밖에서도 읽을 수 있다 | 06의 토큰마다 내부 feature 표시, 원래 위치 번호의 보존, 선택 후 벡터와 가중치의 대응 | 사용자의 방법에 없는 masking, 사진 또는 재구성 성능을 임의로 추가하지 않음 |
| [CLIP Fig. 1](https://arxiv.org/html/2103.00020v1/main-diagrams.png) | 사진과 실제 문구의 묶음, 압축을 연상시키는 encoder 외형, I/T 임베딩, 내적을 적은 대응 행렬, 학습·classifier 생성·예측의 다른 구성 | 구체적인 데이터가 추상적인 연산으로 바뀌며, 서로 다른 패널에서 같은 역할이 이어진다 | 05에 편집 가능한 패턴/문구 쌍, I/T 인덱스, 내적 대각선과 주변 쌍을 도입. 08은 학습과 적용을 다른 내용으로 구성 | 논문에 없는 zero-shot 기능이나 objective를 예제에 억지로 넣지 않음 |
| [U-Net Fig. 1](https://lmbweb.informatik.uni-freiburg.de/people/ronneber/u-net/u-net-architecture.png) | 높이·너비가 달라지는 특징 지도, 채널 수/해상도 수치, U자 공간 배치, 수평 skip, 연산 범례 | 화면의 공간이 해상도 계층과 대응 관계를 표현한다. 외곽 구도 자체가 모델 구조다 | 04에서 특징 평면의 크기를 해상도에 연결하고, 대응 수준끼리 수평 연결. 채널 수가 없으므로 면 개수는 개념도임을 명시 | 원본의 매우 작은 숫자 라벨을 그대로 따라 하거나 실제 채널 수를 지어내지 않음 |
| [Transformer Fig. 1](https://arxiv.org/html/1706.03762v7/Figures/ModalNet-21.png) | 서로 다른 깊이의 두 타워, 반복 enclosure, 덧셈 원, 우회 연결, positional encoding 파형, 연산별 색 | 장식이 적어도 내부 연산과 정확한 연결점이 계층을 만든다. 모든 것을 한 수준의 상자로 취급하지 않는다 | 03에서 상태 열과 확대된 한 블록을 함께 보여주고, 07은 관측/연산/정렬 표현을 서로 다른 형태로 표시 | 내용을 추가할 근거 없이 모든 블록을 펼치거나 반복을 feedback으로 그리지 않음 |

MAE/CLIP의 사진 사용, U-Net의 공간 부호화, Transformer의 내부 연산 표현은 서로 다른 해법이다. 네 작품이 공유하는 한 가지 스타일 템플릿이 있다고 보지 않는다.

## 수정한 8개 예제

| 예제 | 기존 표현의 결손 | 새 표현 |
|---|---|---|
| 01 검색 | Query/Answer/Evidence가 같은 종류의 상자 | 질문 문구, 후보 문서 묶음, relevance/confidence 분해, 근거가 붙은 답변과 소스 |
| 02 분기 | local/global의 차이가 글자뿐 | 공개 NASA 사진, 관심 영역, 확대된 세부와 전체 장면, 두 특징 표현 |
| 03 반복 | ×4와 한 블록만 있어 상태 변화가 약함 | h₀…h₄ 상태 열, θ₁…θ₄, 블록 내부 확대, residual 경로와 식 |
| 04 다중 해상도 | 해상도 숫자가 붙은 같은 높이 상자 | 공간 크기가 달라지는 특징 평면, 수준별 skip, 표현 범례 |
| 05 모달리티 | Image/Text 라벨만 존재 | 네 가지 패턴과 대응 문구, 임베딩 표시, 인덱스를 가진 전체 대응 행렬 |
| 06 토큰 | 번호와 가중치가 떨어져 있어 대응이 약함 | 위치가 남아 있는 토큰, 내부 벡터, 행별 가중치, 가중합 식 |
| 07 긴 라벨 | 라벨을 읽기 전에는 무엇이 바뀌는지 모름 | 불규칙 관측점·오차 표시, 정렬된 신호, 간격/신뢰도 입력 |
| 08 학습/추론 | 단순한 박스 흐름 | 입력 신호, 지도 신호, 구별되는 학습 갱신, 고정 모델의 출력 표현 |

신호, 벡터 막대, 후보 순서, 패턴은 설명용 도식이다. 실제 모델 결과나 측정 데이터처럼 제시하지 않는다. 02의 사진만 실제 공개 샘플이며, 그림의 방법을 그 사진에 실행했다는 의미가 아니다.

## 앞으로의 품질 판단

- 방법의 핵심을 설명하는 표현이 무엇인지 먼저 결정한다. 데이터·상태·변환을 모두 일반 모듈 상자로 바꾸지 않는다.
- 필요한 입력 샘플, 중간 표현, 대응 관계, 공간 계층, 확대 상세 중에서 선택한다. 개수를 채우기 위해 넣지 않는다.
- 장식적 질감이나 막대가 실제 결과로 오해되면 실패다. 데이터가 없으면 개념도임을 표시한다.
- 다른 방법 이름으로 바꿔도 그대로 쓸 수 있는 그림이면, 해당 방법의 고유한 정보가 빠졌는지 검토한다.
- 최종 게재 폭에서 라벨, 주요 비교, 화살표가 읽히는지 확인한다. XML 검사 통과를 시각 품질 점수로 쓰지 않는다.

이번 수정은 피드백에 따른 저자 검토이며, 블라인드 평가나 독립 모델 성능 비교가 아니다.
