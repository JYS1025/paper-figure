# MCP 구현 결정

현재 단계에서는 MCP 서버를 만들지 않는다.

필요한 기능은 `Figure.export`, `pptx.py inspect`, `render.py`, `pptx.py patch`로 한 로컬 환경에서 호출된다. 이 작업의 실제 실패 원인은 export 시 객체 참조, 연결선 경로, 렌더링 차이, 최신 파일 보존 문제였다. MCP 전송 계층은 이 문제를 해결하지 않는다. PowerPoint를 편집기로 유지하며 웹 편집기나 별도 스키마 플랫폼도 만들지 않는다.

여러 에이전트 호스트에서 같은 검증된 엔진을 호출하거나, 도구 발견·권한·파일 전달을 표준화해야 하는 실제 요구가 생기면 얇은 MCP 래퍼를 검토한다. 새 엔진을 만들지 않고 generate / inspect / preview / patch를 그대로 노출하는 것이 다음 후보이다. 서비스 운영·인증·원격 파일 수명 관리와 번들 Artifact Tool 사용 가능 범위를 먼저 확인해야 한다.

이 판단은 현재 구현과 단일 로컬 사용 사례에 근거한다. MCP가 원천적으로 불필요하다는 일반적 결론은 아니다.
